# 02 架构与技术选型

> 定稿日：2026-10-18（M0）。
> 上位依据：`plan/01-题目文档.md`（定稿不改写）、`data/README.md` §4（数值口径唯一出处）。
> 本文只做**结构与边界**决策；每个 `code` / `spec_ref` / 排序 / 时间解析的取值一律引用 `data/README.md` §4，不在此复写。

## 一、交付形态（唯一）

**MCP Server，stdio 传输，零运行时第三方依赖。**

| 项 | 定稿 | 理由 |
| --- | --- | --- |
| 传输 | newline-delimited JSON-RPC 2.0，`stdin` / `stdout` | MCP stdio 传输的协议形态 |
| 运行时依赖 | **无**（仅 Python 标准库） | 干净 clone 即跑；离线可验；协议版本可控；避免 SDK 版本漂移进入判定链 |
| 协议实现 | 自实现 MCP 子集（`initialize` / `notifications/initialized` / `ping` / `tools/list` / `tools/call`） | 首期只需这五个方法；其余方法返回 `-32601`，不假装支持 |
| Python 底线 | **3.8** | 与既有双解释器通道一致；CI 四矩阵 `{ubuntu, windows} × {3.8, 3.12}` |
| 测试依赖 | `pytest`、`PyYAML`（dev extra） | 仅测试期；不进入运行时安装面 |
| 形态排除 | 不做 CLI 判定子命令、不做 Web 服务、不做 GUI | 题面「形态唯一」；CLI/Web 会引入第二条判定入口与第二份契约 |

> **`--version` / `--selftest` 不是第二交付形态**：它们是同一入口的自检开关，不执行判定、不输出 `decision`。判定只能经 `tools/call` 到达。

## 二、分层与依赖方向

```
┌─────────────────────────────────────────────┐
│ transport   字节级读写 / 帧边界 / 上限        │  server.py
├─────────────────────────────────────────────┤
│ protocol    JSON-RPC 2.0 + MCP 生命周期       │  protocol.py / errors.py
├─────────────────────────────────────────────┤
│ toolface    判定结果 → MCP tool 结果          │  toolface.py（isError 映射）
├─────────────────────────────────────────────┤
│ registry    tool 描述符 + 分派（唯一注册表）   │  registry.py
├─────────────────────────────────────────────┤
│ judgement   纯函数判定（T1–T5）               │  judgement/*.py
├─────────────────────────────────────────────┤
│ spec        code 表 / spec_ref / 模板         │  rules.py（生成）；references/codes.json（M1）
└─────────────────────────────────────────────┘
```

依赖方向**单向向下**，由 AST 守门钉住：

- `judgement/` 不得 import `server` / `protocol`（判定层不知道传输存在）；
- `judgement/` 不得 import `time` / `datetime` / `socket` / `ssl` / `http` / `urllib` / `random` / `secrets` / `os` / `subprocess`；
- `judgement/` 只接收来自 `rules.py`（生成物，规格层）的 code 名与模板文本，不自己拼 code 字面量（D41/D42）；
- `protocol.py` 不得 import `judgement/*`（只经 `registry` 分派）；
- 任何层不得读环境变量（`--selftest` 也不读）。

**为什么禁 `os` 而不是只禁 `os.environ`**：`os` 一进来就同时带来 `environ`、`getenv`、`urandom` 三条非确定性路径。禁整包比枚举属性更难绕过，也更容易被 AST 守门完整覆盖。

**镜像规则（单点真相 + 生成侧）**：

- 包内 `src/http_semantics_mcp/references/codes.json` 与 `src/http_semantics_mcp/schemas/tools/*.json` 是**唯一可编辑的真相源**；顶层 `references/`、`schemas/tools/` 是生成镜像。`src/http_semantics_mcp/rules.py` 是同一次生成的 Python 形态（不设顶层镜像：它是模块，不是读者面数据文件；D41）。
- 镜像由 `tools/gen_codes.py`（M1 建立；`--check` 重算比对）生成，仓库内提交；守门 = 逐字节相等。
- 方向固定：**只改包内 → 重生成镜像**。反向手改镜像必被字节相等守门打红。
- 理由：顶层路径是题面交付物与人工阅读面；包内路径是 `importlib.resources` 安装面。同一份内容两处可见，但只有一处可编辑。

## 四、stdio 传输契约

| 项 | 定稿 | 说明 |
| --- | --- | --- |
| 帧格式 | 一行一条 UTF-8 JSON，`\n` 结尾 | 不使用 `Content-Length` 头（那是 LSP 形态） |
| I/O 通道 | `sys.stdin.buffer` / `sys.stdout.buffer`（**二进制**） | 自己编解码，避免 Windows 文本模式的 CRLF 翻译与 code page 影响；跨平台输出字节一致 |
| 换行 | 只写 `\n`；读入容忍 `\r\n` | 读侧剥离尾部 `\r`，写侧永不产出 `\r` |
| 空行 | 跳过，不响应 | 不把空行当错误（客户端可能补换行） |
| 上限 | 单条 8 MiB（`MAX_MESSAGE_BYTES`） | 超限：排空该行至换行、回 `-32600`，进程继续 |
| 编码错误 | 非法 UTF-8 → `-32700` | 不猜测、不替换 |
| 批处理 | 不支持（数组 → `-32600`） | 2025-03-26 起 MCP 已移除 JSON-RPC 批处理 |
| 退出 | `stdin` EOF → 正常退出 0 | 不打印额外横幅到 stdout（stdout 只承载协议消息） |

**stdout 纪律**：任何诊断信息一律走 stderr；stdout 出现非 JSON 行即视为协议污染。守门测试断言 stdout 的每一行都可解析为 JSON。

## 五、MCP 协议子集

### 5.1 生命周期

1. 客户端发 `initialize` → 服务端回 `protocolVersion` / `capabilities` / `serverInfo`，并进入 ready 状态。
2. 客户端发 `notifications/initialized`（无 id，不回包）。
3. ready 之前的其它请求 → `-32002`（`Server not initialized`）。`ping` 例外，始终可用。

### 5.2 协议版本

```python
SUPPORTED_PROTOCOL_VERSIONS = ("2025-06-18", "2025-03-26", "2024-11-05")
DEFAULT_PROTOCOL_VERSION = "2025-06-18"
```

- 请求版本在集合内 → 原样回显；不在集合内 → 回 `DEFAULT_PROTOCOL_VERSION`（规范允许服务端回自己支持的版本，由客户端决定是否继续）。
- 版本集合是**冻结常量**，M0 之后升级需在 `plan/06` 决策记录登记（新增版本不等于支持其中所有可选特性）。
- **不声称**支持 MCP 的 `resources` / `prompts` / `logging` / `completions`：`capabilities` 只声明 `tools`，未声明的方法一律 `-32601`。

### 5.3 方法表

| 方法 | 类型 | 结果 | 状态 |
| --- | --- | --- | --- |
| `initialize` | request | `protocolVersion` / `capabilities` / `serverInfo` | ✅ |
| `notifications/initialized` | notification | 无 | ✅ |
| `notifications/cancelled` | notification | 无 | ✅（接受并忽略） |
| `ping` | request | `{}` | ✅ |
| `tools/list` | request | 已注册 tool 描述符（M0 为 `{"tools": []}`；M2 起 2 个） | ✅ 按注册表如实返回 |
| `tools/call` | request | 判定结果（`isError: false`）/ 坏输入 `isError: true`；未知 tool → `-32602` | ✅ |
| 其它 | request | `-32601` | ✅ |

### 5.4 `tools/list` 与 `tools/call` 的契约

- `tools/list` 返回顺序：按 `name` 的 ASCII 升序（`data/README.md` §4.3 第 5 条的比较规则），不依赖字典插入序。
- `tools/call` 参数：`{"name": str, "arguments": object}`；`arguments` 缺失按 `{}`（M0 无 tool，不影响结果）。
- tool 级错误（输入非法）**不走 JSON-RPC error**：返回 `isError: true` 的 result，`content` 内含 `{"error": {"code": ..., "field": ..., "detail": ...}}`（`data/README.md` §4.6）。
- 协议级错误（方法不存在、参数不是对象、未知 tool）走 JSON-RPC error。
- 判定为 `block` **不是错误**：`isError: false`。

## 六、序列化与确定性

- **唯一序列化点**：`canonical.dumps()`，参数冻结为 `sort_keys=True, ensure_ascii=False, separators=(",",":"), allow_nan=False`。
- 所有出站消息经 `canonical.encode_message()` 编码为 UTF-8 字节 + `\n`；不在别处手写 `json.dumps`。
- 禁止进入输出的量：系统时钟、随机数、进程 ID、主机名、绝对路径、执行耗时、locale 相关格式。
- 守门：同输入双跑，序列化结果 sha256 相等（M0 起常驻；M5 扩到五个 tool 的完整输出）。

## 七、错误契约（协议面）

| 场景 | JSON-RPC code | 行为 |
| --- | --- | --- |
| 非法 JSON | `-32700` | 回 `id: null`，继续 |
| 非法 UTF-8 | `-32700` | 同上 |
| 不是对象 / 批处理 / `jsonrpc != "2.0"` / 缺 `method` | `-32600` | 有 id 则回该 id，否则 `null` |
| 未知方法 | `-32601` | 回原 id |
| 未知 tool / `arguments` 类型错误 | `-32602` | 回原 id |
| ready 之前发请求（`ping` 除外） | `-32002` | 回原 id |
| 服务端内部异常 | `-32603` | 捕获后回包，**进程不退出** |

> `data/README.md` §4.6 的 `error.code` 枚举（`INVALID_INPUT` 等）属于 **tool 面**，不是 JSON-RPC 面；两套码不混用。M1 生成 `codes.json` 时一并生成该枚举，不在代码里手写第二份。

## 八、质量门（M0 起常驻）

| 门 | 实现 | 钉住什么 |
| --- | --- | --- |
| 纯净性 | `tools/gates.py purity`（AST） | 判定链无时钟 / 无网络 / 无 env / 无随机 |
| 绝对路径 | `tools/gates.py paths` | 仓库文本零本机绝对路径（脱敏前置） |
| 行尾 | `tools/gates.py crlf` | 文本文件零 CRLF + `.gitattributes` 在位 |
| 协议握手 | `tools/smoke_stdio.py` + 端到端测试 | 真实子进程可启动、帧无 `\r`、`tools/list` 可解析 |
| 序列化确定性 | 测试 | 双跑 sha256 相等 |
| README 面 | 测试 | 文档提到的命令/旗标/extra 与实物一致 |
| CI 文件 | 测试 | YAML 可解析、矩阵尺寸、无静默放行 |
| 发布门形态 | 测试 | 发布门可跑、离线项报 SKIP、缺件报 FAIL 不崩 |
| oracle 独立性 | `tools/gates.py oracle_independence`（AST） | 生成侧不 import `http_semantics_mcp`（含函数内 import 与 `importlib`） |
| golden 卫生 | `tools/gates.py golden_hygiene` | 冻结件字段齐全、无 `observed_*`；空目录不算通过 |
| code 字面量 | `tools/gates.py code_literals`（AST） | 手写包内源码不出现第二份 code 字面量；`codes.json` 与生成物 `rules.py` 是唯一副本（豁免仅此一条，且缺件即红；D41/D42） |
| 生成物可复算 | `gen_codes --check` / `gen_golden --check` / `golden_coverage` | 重算逐字节一致；覆盖率双向集合等式 |

> 每个门都要**变异验证**一次（把被测行为弄坏 → 门必须红）。M0 落地的门在 `tests/test_purity_gate.py`、`tests/test_release_gate.py` 中带植入式反例。

## 九、CI 形态

- 矩阵：`{ubuntu-latest, windows-latest} × {3.8, 3.12}`，`fail-fast: false`。
- 环境：`PYTHONUTF8=1`、`PYTHONIOENCODING=utf-8`（字符面兜底；协议面已按字节收发，不依赖它）。
- 步骤：安装 `-e ".[dev]"` → 版本/自检 → console script 冒烟 → 仓库门（8 道）→ 生成物可复算（`gen_codes --check` / `gen_golden --check` / `golden_coverage`）→ 变异验证 → stdio 握手冒烟 → 全量 pytest。
- **发布终态门不进 CI**：它在 tag 之前必然因"还没发生的事实"报红；只作为本地/发布期脚本存在。
- **未接远端期间**：所有 CI 类结论一律写"本地等价校验（未接远端，CI 待首推验证）"。M6 首推后据实补记 run id，历史文档保留原措辞。

## 十、被否决的选型（含弃因）

| 选型 | 弃因 |
| --- | --- |
| 官方 `mcp` Python SDK | 引入唯一第三方运行时依赖；SDK 版本漂移会进入"安装面 → 协议行为"链；首期只需五个方法，自实现成本低于依赖成本 |
| FastMCP 装饰器式注册 | 注册表被框架隐式持有，`tools/list` 与 schema 的"字段集合相等"难以做机器对账 |
| `Content-Length` 帧（LSP 风格） | MCP stdio 规定按行分帧；混用会让真实客户端解析失败 |
| 文本模式 `sys.stdin` | Windows 上受 code page 与 newline 翻译影响，跨平台输出字节不一致 |
| 做成 CLI 判定命令（`cors-eval --headers ...`） | 形成第二条判定入口与第二份契约，违背题面「形态唯一」；agent 调用路径应为 MCP |
| 依赖 `http-cache-semantics` | 决策 D6：条款映射不可控，判定会变黑盒 |
