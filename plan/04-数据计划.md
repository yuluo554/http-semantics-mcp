> 定稿日：2026-10-18（M0）。口径唯一出处仍是 `data/README.md` §4；本文只写**数据资产的组织、生成与对账方式**。

| WPT 映射台账 | `data/wpt-mapping.json` | WPT `cors/` 目录逐条登记 | JSON | ✅ 冻结 | M1 建、M5 全量核 |

## 二、golden case 的字段契约

```json
{
  "case_id": "cors-eval-001-basic-allow",
  "tool": "cors_evaluate",
  "input": { "...": "..." },
  "expected": { "...": "完整输出对象" },
  "spec_basis": ["Fetch §CORS check", "RFC9111 §4.2"],
  "source": "synthetic",
  "notes": "可选：为什么构造这条"
}
```

- `expected` 是**完整对象**：键集合 = schema `properties` 集合，不得省略字段（含空数组、空对象、`false`）。
- `source`：`synthetic` | `wpt:<相对路径>`。
- 文件名 = `case_id`，字符集 `[a-z0-9_-]`。
- 冻结后只读；要改期望 → 新立 `case_id` 并在 `data/wpt-mapping.json` 或 `plan/06` 登记原因。

## 三、期望值的独立性（防"引擎自证"）

这是本项目最容易被做假的一环，定死三条：

1. **期望值由独立复算脚本产出**：`tools/gen_golden.py` 用与生产实现**分开书写**的算法（同一规范、两份实现），产出 `expected`。
   - 生产实现在 `src/http_semantics_mcp/judgement/`；生成侧在 `tools/golden_oracle/`。
   - **禁止** `from http_semantics_mcp.judgement import ...`（AST 守门钉住生成侧的 import）。
   - 一致性靠"生成结果 == 生产输出"的逐字节测试，而不是共用代码。
2. **手工构造的用例必须有可复核的小学算术**：如 `max-age=60`、`Age=30`、`resident=30` → `current_age=60` → `is_fresh=false`。用例 `notes` 里写出这行算式。
3. **禁止 `observed_*` 字段**：golden 文件里出现任何"观测"字段即判红（冻结观测会让基准退化成比对两份答案）。

> 若 M1 发现"两份实现"成本过高，允许降级为"生成侧只算**部分独立量**（如 `current_age`、`freshness_lifetime`），动作/判定由规则表复算"，但**必须在 `data/README.md` §3 登记降级理由**，不得静默合并成一份。

**M1 结论：不降级。** 生成侧是完整的第二份实现（五个 tool + 时间解析，见 `tools/golden_oracle/`），只从 `codes.json` 取 `code` / `spec_ref` / 模板文本，算法自行书写。登记在 `data/README.md` §3.5。

## 四、覆盖度矩阵（M1 建、M5 核）

| 维度 | 最低条数 | 必须覆盖的形态 |
| --- | --- | --- |
| 每个 `code` | 1（`data/README.md` §4.1 全表） | 正例或反例至少一条 |
| CORS 边界 | 6 | `Origin: null`；`*` + credentials；`Allow-Credentials` + `*`；预检缺 `Allow-Methods`；`Max-Age` 缺省；`Authorization` 非 safelisted |
| 重定向事件 | 4 | 同源→跨源；跨源→跨源；`credentials_dropped`；`origin_set_to_null` |
| 缓存 | 8 | fresh / stale / `no-store` / `must-revalidate` / `swr` / 无 `Expires` / `Age` 超期 / `max-age=0` |
| 条件请求 | 6 | 四条件两两组合 + 单条件 + 无条件；`W/` 弱标签；`If-None-Match: *` |
| Vary | 6 | 单字段 / 多字段 / `Vary: *` / 字段缺失 / 大小写差异 / 空白差异 |

- 覆盖度由 `tools/golden_coverage.py`（M1）从 `codes.json` ∪ golden 目录实算，输出表并作为测试断言；walk 是递归的，`hops[].violations[]` 里的 code 同样计入。
- **"每个 code 至少一条"是集合等式**：`set(codes.json 的 code) - set(golden 覆盖的 code) == ∅`。反向（golden 里出现 codes.json 之外的 code）也必须为空。

## 五、WPT 映射（M1 建台账，M5 全量核）

### 5.1 获取方式

- 通过 `gh api` 读 `web-platform-tests/wpt` 的 `cors/` 目录树（只取路径 + blob sha + 文件大小），**不复制测试正文入仓**。
- 结果落 `data/wpt/cors-index.json`，登记检索时间与 commit sha。
- 测试正文只在 M1 一次性读取用于**人工判定可否转写**；转写结果落 golden，正文不入仓（避免上游许可与体积问题）。

### 5.2 `wpt-mapping.json` 每条记录

```json
{
  "wpt_path": "cors/preflight-cache.htm",
  "case_ids": ["cors-sim-007-preflight-cache"],
  "mapped": true,
  "reason": null,
  "spec_basis": ["Fetch §CORS-preflight fetch"]
}
```

- `mapped=false` 时 `reason` 必填，取值来自固定枚举：`requires_real_network` / `requires_tls` / `requires_timing` / `browser_proprietary` / `not_header_observable` / `out_of_scope`。
- `mapped=true` 的用例**必须**在 golden 中找到对应 `case_id` 且判定一致（M5 门）。
- 台账头部记录：`wpt_commit`、`fetched_at`（数据日，不是抓取日）、`directory_file_count`。

### 5.3 诚实边界

- WPT 测的是**浏览器行为**，本题是**规范推导**。两者不一致时以规范为准，并在对应 golden 的 `notes` 与 `data/README.md` 登记差异；**不修改期望值去迁就浏览器**。
- 台账里必须显式写"可转写用例数 / 不可转写用例数 / 总数"三个数，且满足 `converted + unmappable == total`（集合划分断言）。

## 六、生成器与冻结纪律

| 生成器 | 产物 | 守门 |
| --- | --- | --- |
| `tools/gen_codes.py`（M1） | `codes.json` + 顶层镜像 | 重生成逐字节一致；代码内无第二份 code 字面量 |
| `tools/gen_golden.py`（M1） | `data/golden/**` | 重生成逐字节一致；`--check` 模式 |
| `tools/gen_schemas.py`（M2+） | `schemas/tools/*.json` + 包内镜像 | 同上 |

- 所有生成器支持 `--check`：重算到内存，与盘上比较，差异即 `exit 1` 并打印首个差异文件与字段。
- 生成产物不含时间戳、不含本机路径、不含文件系统 mtime。
- 生成器本身也要被测试（变异：改坏一个模板 → `--check` 必红）。

## 七、数据目录的 `.gitattributes` 策略

```gitattributes
* text=auto eol=lf
*.json text eol=lf
*.py text eol=lf
*.md text eol=lf
```

- M1 起，凡**字节被 sha256 登记**的件（若将来加入 WPT 原文快照）一律 `-text`。
- 当前计划不引入二进制/TLS 样本，故 M0 `.gitattributes` 只做源码归一。
