## 三、决策记录（D19 起为本轮新增）

> D1–D18 见 `plan/00` §二；此处只登记 M0 新增与细化项。

| 编号 | 决策 | 弃选项 | 弃因 |
| --- | --- | --- | --- |
| **D19** | MCP 传输层用**标准库自实现**（JSON-RPC 子集） | 官方 `mcp` Python SDK / FastMCP | 零运行时依赖；协议行为可控可测；`tools/list` 与 schema 的字段集合相等需要显式注册表 |
| **D20** | Python 底线 **3.8**，CI 四矩阵 `{ubuntu,windows} × {3.8,3.12}` | 3.10+ 底线 / 3.12 单版本 | 与既有双解释器通道一致；扩展可安装面；3.8 兼容成本可控（无异步、无数据类新特性依赖） |
| **D21** | 帧格式 = **按行 JSON + `\n`**，二进制 I/O | `Content-Length` 头 / 文本模式 stdin | MCP stdio 规定按行分帧；文本模式在 Windows 受 newline 与 code page 影响 |
| **D22** | 协议版本集合冻结为三档，未知版本回默认 | 动态探测 / 全版本透传 | 活文档会漂移；"回默认版本"是规范允许的最简确定行为 |
| **D23** | `tools/list` 排序按 name ASCII 升序 | 注册顺序 | 注册表是 dict，顺序在不同 Python 版本语义上不保证一致；排序消除不确定性 |
| **D24** | schema 与 codes 的**唯一可编辑真相源在包内**，顶层为生成镜像 | 顶层为真相源 | 安装形态下只有包内路径可被 `importlib.resources` 读取；顶层路径是人读面 |
| **D25** | M0 的 `tools/list` 返回**空列表**并写进 README | 放占位 tool 描述符 | 占位会让客户端以为能力已存在（违反"对外声称须有实物"） |
| **D26** | `--version` / `--selftest` 作为同一入口的自检开关，不算第二交付形态 | 增加判定类 CLI 子命令 | 判定只能经 MCP 到达，避免第二份契约 |
| **D27** | 期望值生成侧与生产侧**两份独立实现**，靠逐字节测试对账 | 生成侧 import 生产实现 | 同一份实现在两侧会让基准退化成自证 |
| **D28** | 发布附件采用**手工源码包**（`git archive` + `gzip -9n`） | GitHub 自动 Source code / sdist | GitHub 自动包 sha256 本地复算不出；sdist 需要归档归一且易带工作树杂质 |
| **D29** | 发布附件 sha256 **只写 Release 正文**，包内只写复验方法 | 写进包内留档 | 自指：写入动作改变包字节，哈希立刻失效 |
| **D30** | 不引入 `http-cache-semantics` 等第三方语义库（强化 D6） | 依赖成熟库 | 条款映射不可控；依赖会进入"安装面 → 判定"链 |
| **D31** | 单条消息上限 8 MiB，超限排空该行并回 `-32600` | 无上限 / 直接断连 | 无上限可被单行打爆；断连会让客户端误判会话死亡 |
| **D32** | 所有出站消息经 `canonical.dumps()` 单点序列化 | 各处 `json.dumps` | 多写点必然漂移（分隔符/键序/中文转义） |
| **D33** | 判定层禁止 `import os`（不只是 `os.environ`） | 只禁 `environ` | `os` 还带 `urandom`、`getenv`、`system` 等非确定性/副作用面；整包禁更易被 AST 完整覆盖 |
| **D34** | 发布终态门**不进 CI**，只做本地/发布期脚本 | 挂进 CI 当常驻门 | tag 之前它必然因"还没发生的事实"报红，红得没有信息量 |

### M2 新增（D41–D43）

| 编号 | 决策 | 弃选项 / 结论 | 弃因 |
| --- | --- | --- | --- |
| **D41** | 规则表的 **Python 形态由生成器产出**：`gen_codes.py` 除 `codes.json`（包内 + 顶层镜像）外，再渲染 `src/http_semantics_mcp/rules.py`（`CATALOG` 字面量 + 每个 `code` 一个同名常量）；判定层 `from ..rules import ...` 按名引用，**手写源码里不出现 code 字面量** | ①判定层用 `importlib.resources` 读 `codes.json`；②生成 `references/codes.py`；③放宽 `code_literals` 为"字面量必须在表内"；④运行时用前缀拼出 code | ①仍走 `open`/`read_text`，被判定层禁盘门打红，并给判定链加一层 IO 失败面；②`references/` 是**数据目录**（`tests/test_packaging.py` 要求任何含 `*.py` 的子目录成为包），且 `setuptools.packages.find` 不安装非包目录下的模块 —— 安装态读不到，正好违背 M1 建立的"安装面须能读到口径"；③会把 M1 的"code 唯一副本"口径作废，并让既有变异用例失去意义；④是靠正则边界绕门，抗漂移性质不比 D41 强 |
| **D42** | `code_literals` 门对生成物 `rules.py` 做**精确单点豁免**：仅该路径被跳过，且门额外断言"该文件存在且含 `CATALOG`"（缺件即红，豁免不得变成空洞）；`gen_codes --check` 逐字节守门，`tests/test_gen_codes.py` 断言 `rules.CATALOG == codes.json` 且常量名集合 == 表内 code 集合 | 让门只管 "`references/codes.json` 之外的 `src/**.py`"（不检查生成物是否存在） | 豁免一个不存在的文件 = 门扫到零个可豁免件，等于把"查不到"当成"没问题"，与 `tools/run_gates.py` 的"零扫描即失败"口径冲突 |
| **D43** | M2 的 tool 描述符用**内联 `inputSchema`**；五个 tool 的正式 schema 文件（`schemas/tools/*.json` + 包内镜像）与"schema `properties` 键集合 == 实跑输出键集合"门**推到 M5** | 按 `plan/05` M2 产出原措辞在 M2 就生成 schema | 输出键集合已由 `data/README.md` §4.10 在 M1 冻结，M2 生成的 schema 在 M3/M4 加 tool 时必然要重生成一次；`plan/03` §六 已把"字段集合相等"定为 M5 硬门。`plan/05` M2 产出按本决策修正，不留下两句打架的口径 |

### M3 新增（D44–D46）

| 编号 | 决策 | 弃选项 / 结论 | 弃因 |
| --- | --- | --- | --- |
| **D44** | T3 的 Age 取值优先级：`stored.age`（入库时记录的 Age）**优先于**响应头 `Age`，后者只在 `stored.age` 缺失时兜底 | ①只读响应头 `Age`；②两处都读并取较大者；③`stored.age` 与响应头不一致时判为输入错误 | ①会打挂 `cache-001/002/017`（这三条把 Age 放在 `stored` 上，响应头里没有 `Age`）；②`max()` 是两条记录语义的发明，规范只定义"入库存下来的 Age"一个量；③规范没有"不一致即错误"这回事，且会让合法输入变成 tool error |
| **D45** | 时间解析的"只截断、不进位"覆盖**两种**末位：ISO 亚秒 `.999Z` 与 `:60` 闰秒都向下折到该分钟的最后一秒（`min(second, 59)`） | 亚秒截断但放行 `:60` 进算术 | 同一秒内两种进位规则会让"同一瞬间的两种写法"落到不同秒，破坏 golden 的字节可复现；`time-003` / `time-007` 已把亚秒侧钉死，闰秒侧沿用同一条纪律 |
| **D46** | `stale-while-revalidate` 的**边界**（`current_age - freshness_lifetime == window`）不新增 golden，改由 `tests/test_cache_golden.py::test_stale_while_revalidate_window_boundary_is_inclusive` 直接构造输入断言 | 新增一条 `cache-019-*` golden | M3 的验收基线是"M1 冻结的 18 条 golden 逐字节相等"，黄金用例在 M1 冻结后只读（`data/README.md` §3.2）；边界属**生产实现**的 `<=` 口径（`plan/03` §3.2），用测试钉住既不改基准，又能让"去掉等号"这条变异变红（变异 23） |
